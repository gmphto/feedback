# Current stack

Use a TypeScript modular monolith with separate pnpm `client` and `server` packages. Each package owns its dependencies and strict TypeScript configuration; client and server wire types remain separate.

Installed: React 19, Vite, Tailwind CSS 4, TypeScript and client Vitest; Fastify 5, TypeScript and tsx on the server. Server tests use Node's built-in test runner through tsx, not Vitest. Focused readiness/configuration tests require no external services. The full suite includes real PostgreSQL integration tests with a separately supplied TEST_DATABASE_URL.

Client authentication, project workflow/draft state and saved representations use private per-factory Redux Toolkit 2.12.0 stores with Immer draft recipes. Redux Toolkit listener middleware owns model effects; React subscribes through useSyncExternalStore. Stores expose only getState and subscribe; commands and the API facade own mutations. The model owns mutation and cancellation; components render state and invoke commands through the API facade. Server authentication uses openid-client 6.8.8 and @fastify/cookie 11.1.2, approved for issue #4. Installed server database tooling is Kysely with pg and its development types; PostgreSQL remains authoritative persisted state. Add dependencies only after user approval. Use JSON Schema for runtime transport validation, integer relational identifiers, and plain exported commands. Do not use Zod, shared wire packages, or class-based processors.

Keep domain rules outside React and HTTP handlers, and deterministic decisions separate from database, network, AI, time, and logging effects. Separate cached server state from editable drafts, with one mutation authority per representation and lifecycle phase. Reject stale aggregate writes using optimistic concurrency. Calculate reliable derived values from authoritative facts.

AI output is untrusted: validate it before creating drafts or proposals, and never let it directly mutate approved scope or calculate health. Use Server-Sent Events for AI response streaming. Do not add WebSockets, microservices, brokers, graph databases, or vector databases without new evidence.

Auth0 configuration belongs to issue #4; hosting belongs to later issues. Archived stack statements do not authorize additional tools or dependencies.

Authentication persistence uses integer users unique by issuer and subject, SHA-256 digests of cryptographically random session identifiers, and browser-bound login transactions consumed with atomic DELETE RETURNING. Identity upsert and session insert share a database transaction. Absolute session expiry is eight hours; login transactions expire after ten minutes, using an injected clock. OIDC Authorization Code uses PKCE S256 and explicit signature verification through openid-client; provider tokens stay server-side and are not persisted.

Authentication configuration targets an Auth0 Regular Web Application with server-only client credentials, a normalized HTTPS issuer and a configured application origin that determines the callback. Explicit local HTTP is restricted to literal loopback hosts in development/test; HTTPS always requires Secure cookies. Production wiring fails closed with sanitized unavailable responses. Unsafe authentication requests require the exact application Origin; the callback uses browser-bound single-use state/nonce. Fastify automatic per-request logging is replaced by route/status-only completion logs so callback queries and raw provider errors are not logged by framework request logging.

The server project module owns all project persistence access. Every exposed query/command requires an authenticated actor, and SQL constrains the owner directly. Nested reads join features → feature areas → projects and constrain every supplied parent plus owner in that operation. The module exposes no unscoped lookup/update or arbitrary callback into its database. Creation assigns the actor's ID; exposed commands never accept submitted owner/identity fields. Name changes lock an owner-scoped row and update with an expected-version predicate in one transaction, returning a scoped conflict representation for stale owner writes. Lists apply ownership and literal case-insensitive filtering before stable name/ID ordering and pagination.

Issue #6 exposes creation through the same module with one atomic insert of name and seven optional starting-context strings. Definition reads remain owner-scoped; summary/list/name-update contracts stay separate and unchanged. The context migration supplies empty strings for old projects. The client form model alone mutates the draft; its API facade alone mutates saved representations. Redux Toolkit listener effects own cancellation and history navigation, with operation/session/route checks gating both cache commits and late responses. Browser history supports create/saved routes without a router dependency. Cancelling a dispatched create stops observation, not a possible server commit; no automatic POST retry or independent-request idempotency is claimed. Nested rows remain minimal identity/parent links for later migrations to extend.
